# Відео-демо (2–3 хвилини) і пояснення для пари 2

У завданні: у демо має бути видно **запуск системи**, **виклики інструментів у лозі**, **одну помилку і вихід із неї** і **кінцевий результат** (новий рядок у файлі).

## Підготовка (до запису)

```bash
uv sync
uv run pytest -q                                   # 34 тести проходять
rm -rf runs                                         # чистий старт
```

## Сценарій запису

| Час | Що показати | Що сказати |
|---|---|---|
| 0:00–0:25 | Слайд [`architecture.png`](architecture.png) | Два агенти. Scout шукає й пише листи, інструмента `apply` у нього немає. Reviewer перевіряє й єдиний має право писати. Інструменти дає наш MCP-сервер `jobdesk`: `search_jobs`, `get_job`, `apply`. |
| 0:25–0:40 | `cat data/candidate/cv.md` (прогорнути) | Кандидат вигаданий. Агенти мають право використовувати лише факти з цього CV. |
| 0:40–2:10 | Запуск нижче; у консолі видно кожен виклик інструмента | Коментувати, коли з'являться червоні рядки (див. «Що має бути видно»). |
| 2:10–2:40 | Блок «applications.csv» наприкінці запуску, потім `cat runs/*/workspace/mcp_calls.jsonl` | Нові рядки з'явилися лише для двох вакансій. Аудит сервера показує роль кожного виклику. |
| 2:40–3:00 | `evaluation/results/<stamp>/report.md` | Скільки запитів з 5 пройшло в системі з двома агентами й у варіанті з одним, і чого це коштувало. |

Команда запуску (запит c5: перший найкращий варіант уже є у відгуках, а наступний закрито):

```bash
uv run python -m jobdesk.run --seed J-108 "Apply to the 2 best remote Python/Django jobs for me."
```

## Що має бути видно (і де)

| Вимога з завдання | Де в запуску |
|---|---|
| Новий рядок у файлі наприкінці запуску | блок `applications.csv` у кінці: рядки `APP-0002`, `APP-0003` з роллю `reviewer` (рядок `APP-0001` з роллю `seed` був до запуску) |
| У консолі видно, які інструменти викликались | рядки `→ search_jobs(...)`, `→ get_job(...)`, `→ apply(...)` з назвою агента `[scout]` / `[reviewer]` |
| Одна відмова й вихід із неї | `✗ apply → already_applied` на J-108: Reviewer не дублює відгук і переходить до запасної вакансії; `✗ apply → needs_input` на J-101: відповідає на питання форми з профілю й CV і повторює виклик успішно |
| Чому писати може лише один агент | `AGENT_ROLE=scout`: тест `test_scout_cannot_write_and_nothing_is_written` показує `forbidden` і відсутність файлу |

## Додатково (за часом)

Показати сервер окремо від агентів, як його бачить будь-який MCP-клієнт:

```bash
AGENT_ROLE=single_agent npx @modelcontextprotocol/inspector uv run python -m jobdesk.server
```

Показати трейс у вигляді сторінки:

```bash
uv run python scripts/trace_view.py runs/<run>/trace.jsonl --html /tmp/trace.html
```

## Питання, до яких варто бути готовим

- **Чому два агенти, а не один?** Див. [`ARCHITECTURE.md`](ARCHITECTURE.md), розділ «Чому розподіл саме такий», і висновки в [`../RESULTS.md`](../RESULTS.md).
- **Як ви гарантуєте, що Scout не напише?** Два шари: його немає в списку інструментів, і сервер перевіряє `AGENT_ROLE`.
- **Агент ходить через MCP чи імпортує функцію?** Через MCP: SDK запускає `python -m jobdesk.server` як stdio-підпроцес. `store.py` агенти не імпортують.
- **Як перевіряли, що результат правильний?** Грейдери читають `applications.csv` і аудит-лог сервера, а не слова агента, і самі перевірені тестами в `tests/test_graders.py`.
